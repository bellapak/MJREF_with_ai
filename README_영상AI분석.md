## 기능
1. 영상 카드 클릭 → 상세 패널 맨 위 **AI 영상 분석**.
2. **빠른 분석 (기본):** 브라우저에서 영상 중간 시점 6개 프레임을 JPG(최대 가로/세로 512px)로 추출. 음성/사운드는 분석하지 않음. 영상 원본을 서버로 보내지 않고 로컬에서 프레임을 만들지만, 프레임은 Google Drive와 Gemini API로 전송됩니다.
3. **정밀 분석 (선택):** 실제 영상+오디오를 Gemini 모델에 전송. **원본 12MB 이하**, MP4/WebM 등 지원하는 파일만 가능. 이 제한은 Apps Script의 요청 크기 및 인라인 입력 한계에 안전 여유를 두기 위한 것입니다.
4. 파일 업로드 자체로는 AI 호출하지 않음. 한 번 `mjrefAnalyzePendingVideos`를 수동 실행할 때 **대기 중인 영상 1개**만 분석.
5. 결과는 `summary, hook, structure, visualStyle, marketingAngle, creatorRole, audio, cutRhythm, limitations`와 분류 추천을 카드별로 보관.
6. 추천 태그는 **`추천 분류 태그 반영`을 클릭해야** 기존 태그에 합쳐집니다. 기존 필터를 지우지 않습니다.
7. 결과 화면의 토큰 수는 API가 반환한 값입니다. 비용은 **참고용 유료 표준 요금 계산**이며 실제 청구서와 다를 수 있습니다.

## 꼭 필요한 최초 1회 설정
1. 기존 GitHub 소스를 **백업**하고 `app.js`와 `styles.css`만 바꿉니다.
2. 기존 **Apps Script 프로젝트**를 열고 새 스크립트 파일을 만듭니다. 이름 `VideoAnalysis.gs`. 이 ZIP의 파일 내용을 붙여 넣습니다. **기존 `Code.gs`를 덮어쓰지 마세요.**
3. Apps Script 편집기 **프로젝트 설정 → 스크립트 속성**에서 `GEMINI_API_KEY` 속성을 추가하고, Google AI Studio에서 발급한 Gemini API 키를 값으로 입력합니다.
4. 모델 기본값은 `gemini-3.5-flash-lite`입니다. 다른 모델을 써야 하는 경우 스크립트 속성 `MJREF_VIDEO_MODEL`을 해당 지원 모델 ID로 설정할 수 있습니다.
5. Google Drive 읽기·쓰기와 외부 URL 요청(UrlFetchApp)에 대한 Apps Script 권한을 최초 실행 시 승인합니다.
6. **절대로 API 키를 HTML·app.js·GitHub에 올리지 마세요.** 웹 브라우저에 API 키를 입력하는 UI는 제공하지 않습니다.

## 영상 1개 분석 실행 흐름
1. MJREF에서 영상 카드 클릭 → **빠른 분석** 또는 **정밀 분석** 선택 → **선택 모드 분석 준비** 클릭.
2. **분석 준비 완료**가 나오면 상단 **Drive에 저장** 클릭. 이 과정에서 원본 영상(미저장 시)과 대표 프레임(빠른 분석)을 Drive에 업로드합니다. 성공을 확인합니다.
3. **Apps Script 열기** → 함수 선택 목록에서 `mjrefAnalyzePendingVideos` → **실행**. 한 번 실행하면 **대기 중인 영상 하나**를 분석합니다. 실행 로그로 오류 확인.
4. 해당 MJREF 영상 상세로 돌아와 **결과 가져오기 ↻** 클릭. 불러오기는 해당 영상의 결과만 병합하므로 다른 레퍼런스를 덮어쓰지 않습니다.
5. 원하는 경우 **추천 분류 태그 반영** 클릭.
6. 마지막에 **Drive에 저장** 버튼을 다시 눌러, 로컬로 가져온 결과와 추천 태그를 Drive에 반영합니다.

## 데이터 보존 및 오류 대처
- 드롭한 이미지/영상은 기존처럼 로컬과 Drive 수동 저장 방식입니다.
- 프레임은 `refboard-assets/video-analysis-frames`에 저장하여 일반 레퍼런스 이미지로 추가되지 않습니다.
- Apps Script가 새 결과를 Drive JSON에 기록한 상태에서 로컬의 낡은 `queued` 요청으로 덮어쓰는 동작을 감지·차단합니다. 해당 경우 영상 상세에서 **결과 가져오기**를 먼저 실행합니다.
- `Drive 불러오기`는 전체 로컬 상태를 덮어쓸 수 있으므로 영상 결과 동기화 목적으로 사용하지 마세요.
- 원본이 로컬에서 복구되지 않거나 브라우저가 코덱을 디코딩하지 못하면 프레임 추출은 실패할 수 있습니다. Chrome에서 MP4(H.264) 또는 WebM을 권장합니다.
- 다른 계정/프로젝트나 여러 `refboard-assets` 폴더가 있으면 Apps Script가 잘못된 Drive 파일을 볼 수 있습니다. 폴더 중복 상태를 정리해야 합니다.
- 기존 AI 이미지 분류의 `classifyNextBatch` 기능은 변경하지 않았습니다. 영상 분석은 별도 함수/별도 Gemini API 키를 씁니다.
