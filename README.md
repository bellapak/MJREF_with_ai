# 레퍼런스 탐색기 — Drive 자동저장 상태 + 캐러셀 클립보드 붙여넣기

## GitHub 적용
기존 GitHub Pages 저장소의 `index.html`, `app.js`, `styles.css` 3개 파일만 교체하세요. `apps_script/Code.gs`는 이전 버전 그대로 동봉했으며 이 업데이트로 변경할 필요가 없습니다.

## 바뀐 동작
- 상단 **Drive 저장** 수동 버튼 제거
- 상태 표시: **저장 중… / Drive 저장 완료 / Drive 저장 실패 · 재시도 / 브라우저에 저장됨 · Drive 연결 필요**
- 저장 실패 시 상태 표시를 눌러 재시도할 수 있습니다.
- 짧은 시간에 여러 건이 변경되어도 저장 업로드를 순서대로 처리합니다.
- Google Drive JSON의 수정 시간을 비교해 다른 장소에서 수정된 데이터를 덮어쓰는 상황을 감지합니다.
- 브라우저 클립보드에 **여러 개 이미지 파일**이 들어 있고 한 번에 Ctrl+V/⌘+V하거나 `클립보드 읽기` 버튼을 누르면 **한 캐러셀 항목**으로 추가합니다.
- 이미지 1개는 기존처럼 단일 이미지 항목입니다. 영상은 별도 아이템입니다.
- 캐러셀 항목은 기존 `type:'carousel'` 및 `carousel:[slide...]` 형태 그대로 저장됩니다.

## 꼭 확인할 점
1. 첫 설치 후 Google 연결 → **Drive 불러오기**를 한 번 눌러 현재 Drive 저장본을 기준으로 시작하세요. 이 순서가 지켜지지 않으면 충돌 방지를 위해 자동 저장을 보류하고 오류를 표시할 수 있습니다.
2. Drive 연결 이후 추가/수정/붙여넣기는 자동 저장됩니다. **저장 완료** 상태가 나올 때까지 브라우저를 닫지 마세요.
3. 다른 탭 또는 Apps Script에서 분류를 마친 경우, 브라우저의 저장 상태가 더 오래되었으면 **Drive 저장 실패 · 재시도**가 나타날 수 있습니다. 이전 웹 편집을 유지할 필요가 있다면 먼저 별도로 백업한 후 최신 Drive 데이터로 새로고침하세요. `Drive 불러오기`는 로컬 상태를 최신 원본으로 덮어쓸 수 있습니다.
4. 클립보드에서 여러 파일이 동시에 제공되는지는 OS/앱/브라우저에 따라 달라집니다. Finder, 이미지 편집기 등에서 여러 이미지 복사를 하더라도 브라우저에 한 개만 전달되는 환경이 있습니다. 그런 경우 기존 **레퍼런스 추가 → 캐러셀 → 여러 파일 선택** 방식은 그대로 이용할 수 있습니다.
5. **파일 입력기의 여러 개 일괄 업로드는 기존처럼 단일 이미지 여러 장입니다.** 캐러셀로 묶는 새 동작은 동일한 붙여넣기 이벤트에서 **여러 이미지가 전달된 경우**에 적용됩니다.
