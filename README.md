
# 상세페이지 모음 추가 · 2026-11-12

## 새 기능
- 상단 **레퍼런스 / 카피 모음 / 상세페이지 모음**으로 분리.
- 기존 상세페이지 데이터는 이동 또는 복제해 삭제하는 방식이 아닙니다. `items` 안에 원본 미디어·메모·태그를 보존하고, **상세페이지 모음 화면에서만 따로 표시**합니다.
- 기존 `상세페이지` 분류 태그, 명시적인 상세페이지 제목/파일명, 정확히 일치하는 과거 카테고리는 자동 구분합니다. `랜딩/상세페이지`처럼 합쳐진 카테고리는 **분류 확인이 필요한 기존 자료**에서 수동 선택합니다. 기존 자료의 자동 소구 태깅은 하지 않습니다.
- 일반 레퍼런스 상세에서 **상세페이지로 분류** / 상세페이지 상세에서 **일반 레퍼런스로 이동** 기능 제공. 각각 기존 레코드에 분류 표시만 변경하므로 되돌릴 수 있습니다.
- 상세페이지별 **제품 카테고리 / 복수 소구 포인트 / 구성 단계 / 메인 카피 / 소구별 카피·근거 / 구성 메모**를 수동 입력하고 검색·필터링할 수 있습니다. **전체 보기**로 긴 이미지·캐러셀을 확대해 확인할 수 있습니다. 카테고리 및 소구 포인트 직접 추가 가능.
- 기존 그리드 카드, 썸네일, 미디어 다운로드, 원본 링크, 레퍼런스 편집, Enter 저장, 로컬 저장·Drive 수동 저장 체계를 유지합니다. 카피와 연결된 콘텐츠도 원래 분류 페이지로 열립니다.
- 주의: **기존 전체 삭제** 버튼은 이제 **일반 레퍼런스만** 삭제합니다. 상세페이지는 카드별 삭제해야 합니다.

## 적용 방법
1. 운영 브라우저에서 상단 **Drive에 저장**을 눌러 현재 데이터를 백업하고, 가능하면 Drive의 `refboard-data.json` 사본도 보관합니다.
2. ZIP에서 `app.js`, `index.html`, `styles.css` 3개 파일을 기존 GitHub Pages 저장소에 교체하여 같은 URL로 배포합니다.
3. 새로고침 후 **상세페이지 모음**으로 이동, 자동 분류된 목록과 '분류 확인이 필요한 기존 자료'를 확인합니다.
4. 한 건의 카테고리/소구 포인트를 시험 저장하고 다시 열어 확인한 뒤 상단 **Drive에 저장**을 눌러 백업을 반영합니다.
5. 기존 Apps Script/Google Cloud 설정 변경은 필요하지 않습니다.

## 저장 및 주의
- 상세페이지의 소구/카피 내용은 실제 자료 확인 없이 추정·생성하지 않습니다. 새 분류 필드는 초기 미입력 상태입니다.
- 새 필드는 기존 JSON의 미디어 `items[].detailPage` / `items[].collectionKind`에 저장됩니다. `copyNotes`는 변경하지 않습니다. 이미지/영상은 기존 Drive 에셋을 그대로 참조합니다.
- 기존 `랜딩/상세페이지` 혼합 카테고리에는 랜딩페이지가 포함될 수 있어 자동 제외하지 않았습니다. 목록에서 수동 확인해 주세요.
- 이전 버전 코드로 되돌린 후 Drive에 저장하면 신규 필드가 손실될 수 있으니, 버전 교체 시 JSON 백업을 남겨주세요.

## 검증
- 정적 문법 검사와 코드 단위 테스트 수행.
- 실제 운영 사이트, Google 계정 OAuth 및 업로드/다운로드는 배포 후 검증이 필요합니다.

# 카피 모음 페이지 추가 · 2026-11-10

## 적용
이 묶음의 `index.html`, `styles.css`, `app.js` 세 파일을 기존 사이트의 같은 이름 파일로 교체하세요.
기존 배포 주소에서 적용해야 같은 브라우저의 기존 로컬 데이터가 이어집니다.
기존 Apps Script 코드를 교체할 필요는 없습니다.

## 사용
- 상단 **카피 모음** → 마음에 든 카피 입력 → 좋았던 이유를 간단히 작성 → **카피 저장**.
- 이유는 선택 입력이며, 줄바꿈을 지원합니다.
- Enter: 줄바꿈 / Ctrl 또는 ⌘ + Enter: 저장. 한글 조합 중에는 실행하지 않습니다.
- 저장된 카드에서 검색·수정·삭제·문구 복사가 가능합니다.
- 저장 버튼은 브라우저 로컬 저장입니다. 다른 기기에서 보려면 기존 **Drive에 저장**을 눌러주세요.
- 카피는 기존 Drive 데이터 JSON의 `copyNotes`에 저장됩니다. 기존 이미지/영상 `items`와 분리했습니다.
- 구버전 Drive JSON에 copyNotes가 없으면 로컬 카피를 유지하고 Drive 저장 필요 상태를 표시합니다.
- copyNotes가 포함된 Drive 파일을 명시적으로 불러오면 그 파일의 카피 목록으로 교체합니다. 저장하지 않은 로컬 변경은 기존 확인창으로 안내합니다.
- 기존 ‘전체 삭제’는 미디어 레퍼런스에만 적용됩니다. 카피는 카드별 삭제를 사용하세요.
- 입력 중 페이지를 전환해도 내용은 유지되며, 저장 전 창을 닫으면 브라우저에서 이탈 경고를 시도합니다.

## 확인한 범위
- 실제 미리보기: 카피 작성, 저장, 수정, 검색, 새로고침 후 로컬 저장 유지.
- 코드: JavaScript 문법, 기존 데이터와 카피의 함께 저장/복원, 저장 실패 시 메모리 되돌림.
- Google Drive 계정 로그인 후 실제 업로드/다운로드는 이 환경에서 실행하지 않았습니다.
- 테스트 카피는 배포 파일에 포함하지 않았습니다. 운영 사이트 배포는 아직 하지 않았습니다.

# MJREF 영상 수동 분류 전용 (2026-10-26)

## 변경 범위
- 기존 최신 `MJREF_영상_자동태그_자동반영_20261026.zip` 기반 **최소 변경**입니다.
- `app.js`: 영상 전용 AI 자동 태그/프레임 추출/분석 요청/결과 동기화/20초 폴링/영상 프레임 Drive 업로드 및 대기 검사 제거.
- 영상 카드의 상세 패널에는 기존 **분석 분야 → 공통 분석 → 분야별 심화 → 비주얼** 수동 체크 태그만 남깁니다. 선택 후 `수정 저장`을 눌러 저장합니다.
- 이미지·캐러셀·영상 업로드 및 재생, 기존 데이터, 기존 분류 필터, 캐러셀, 조회수·좋아요·댓글 수, 일반 이미지 AI 분류 `Code.gs`, 브라우저 로컬 자동 저장/Drive 수동 저장은 유지합니다.
- 기존 데이터 속 `videoAnalysis` 이력은 **삭제하거나 초기화하지 않습니다**. 화면에서 사용하지 않고 신규 분석 요청을 만들지 않습니다.

## 설치 (둘 다 진행 권장)
1. **GitHub 저장소 및 로컬 변경사항을 먼저 백업하세요.** 특히 아직 Drive에 저장하지 않은 새 이미지·영상이 있으면 브라우저 데이터/IndexedDB를 삭제하지 마세요.
2. GitHub Pages 저장소의 `app.js` 파일을 이 ZIP의 `app.js`로 **교체**합니다. `index.html`과 `styles.css`는 변경하지 마세요. GitHub Desktop에서 Commit → Push origin 합니다.
3. Google Apps Script 편집기에서 기존 `VideoAnalysis.gs` 파일의 내용을 이 ZIP의 **비활성화 버전**으로 교체합니다. 이 두 함수는 호출돼도 아무 분석을 실행하지 않습니다. (대신 해당 파일을 삭제하려면 먼저 이 함수에 연결된 트리거가 없는지 확인하세요.)
4. Apps Script > 트리거(시계 아이콘)에서 `mjrefAnalyzePendingVideos` 또는 `mjrefBackfillVideoTags`에 대한 예약 트리거가 있으면 **삭제**합니다. `classifyNextBatch` 등 이미지 AI 자동 분류 트리거는 건드리지 마세요.
5. 배포 후 영상 카드 열기 → **콘텐츠 분석 분야 / 수동 필터 체크** → `수정 저장` → 상단 `Drive에 저장`. 새로고침 후 태그가 남는지 확인하세요.

## 참고
- 현재 파일의 태그는 수동 입력만 가능하며 영상 AI 크레딧을 사용하지 않습니다.
- 기존에 AI로 등록된 태그가 있다면 **삭제하지 않고 그대로 남습니다**. 필요 없는 태그는 영상 상세에서 체크 해제 후 수동 저장하면 됩니다.
- Google Drive의 기존 영상 분석 프레임 폴더는 자동 삭제하지 않습니다. 보존 여부가 확실하지 않으면 그대로 두세요.
- `Drive 불러오기`는 저장되지 않은 로컬 변경사항을 덮어쓸 수 있으니, 필요하지 않으면 누르지 마세요.

## 2026-11-06 · 상세 편집 Enter 저장

- 카드 선택 → 우측 **상세 수정** 패널의 제목, 브랜드, 조회수/좋아요/댓글, 원본 링크, 대표 색상 HEX 및 분류 태그 입력 상태에서 **Enter**를 누르면 기존 **수정 저장** 버튼과 동일하게 저장합니다.
- **기타 메모**의 일반 Enter는 줄바꿈을 유지합니다. 메모를 저장할 때는 **Ctrl+Enter(Windows)** 또는 **⌘+Enter(Mac)** 를 사용합니다.
- 한글 입력 조합 확정에 사용하는 Enter는 저장하지 않도록 처리했습니다.
- '원본 열기', '삭제', '되돌리기' 등 버튼의 원래 키보드 동작을 가로채지 않습니다.
- 저장되는 범위는 **기존과 동일하게 브라우저 로컬 데이터**입니다. 다른 기기에서도 동일하게 보려면 상단 **Drive에 저장** 버튼을 별도로 눌러야 합니다.
- 배포 시 기존 자료를 백업한 후 **`app.js`만 교체**하면 됩니다. `index.html`, `styles.css`는 원본과 동일합니다.
- 정적 검사 `node --check` 통과, 키보드 동작 단위 테스트 15개 통과. 실제 Google Drive 계정 및 운영 사이트의 동작은 별도로 확인해야 합니다.


## 카피와 콘텐츠 연결
카피 작성·수정 화면의 `콘텐츠 연결`에서 모아둔 콘텐츠를 검색하고 선택한 뒤 저장합니다. 여러 콘텐츠를 선택할 수 있습니다. 카피 카드의 `콘텐츠 보기` 버튼으로 기존 상세 화면을 엽니다. 선택을 해제하고 저장하면 연결만 해제됩니다. 연결 정보는 기존 카피와 함께 브라우저 및 Drive 저장 데이터에 포함됩니다.
