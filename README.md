# MJREF 영상 AI 자동 태그 수정 (2026-10-26)

## 무엇이 바뀌었나

**이번 수정의 출력은 긴 분석 결과가 아니라 기존 MJREF 분류 태그(`item.facets`)입니다.**

- **근본 오류 수정**: 이전 `VideoAnalysis.gs`는 `videoAnalysis.result.suggestedFacets`에만 분류값을 저장했고, 수동 `추천 분류 태그 반영` 버튼을 눌러야 `facets`에 반영되었습니다. 이제 `mjrefAnalyzePendingVideos`가 Gemini 분석에 성공하면 동일한 트랜잭션에서 기존 `facets`에 유효한 태그를 자동 병합해 `refboard-data.json`에 저장합니다.
- **기존 필터 24개 연결**: 상위 분석 분야, 인플루언서 유형/형식, 브랜드 협업 관계, 콘텐츠 역할, 마케팅 전략, 채널, 색상군, 비주얼 스타일 등. 태그 사전은 함께 제공된 사용자 `app(5).js`의 `FACETS`에서 추출했습니다. 앱에 존재하는 정확한 선택지만 허용합니다.
- **데이터 보존**: 수동 태그, 이름, 메모, `socialMetrics`(조회수/좋아요/댓글), 미디어/캐러셀, 기존 AI 영상 기록은 지우지 않습니다. 중복 태그는 추가하지 않습니다.
- **분석 결과 화면 간소화**: 영상 상세에는 자동 적용 태그와 처리 상태만 표시합니다. 긴 설명문은 출력하지 않습니다.
- **성공 영상 소급 반영**: 신규 Apps Script 함수 `mjrefBackfillVideoTags()`로 이미 끝난 분석의 `suggestedFacets`를 **새 Gemini 호출 없이** 실제 태그로 옮깁니다. 유효한 태그가 없었던 분석은 소급 생성되지 않습니다.
- **실패 영상 재시도**: 저장된 프레임 6장(Drive ID 모두 존재) 또는 Drive에 저장한 정밀 분석 원본을 그대로 재사용해 다시 분류를 요청할 수 있습니다. 재시도 자체는 Gemini API 비용이 추가로 발생할 수 있습니다.
- **간헐 오류**: Gemini의 429/5xx 응답에서만 1회 재시도. 잘못된 MIME, 초과 용량, 프레임 누락은 구체적인 원인 메시지로 처리합니다. API 키는 계속 Apps Script 속성에만 보관합니다.
- **브라우저 동기화**: 사이트에서 해당 영상의 분석 요청을 열고 Drive 저장까지 완료하면 약 20초 간격으로 결과 태그만 확인합니다. 완료된 태그만 로컬로 병합하고 제목/메모/입력 중인 성과 지표는 덮어쓰지 않습니다. 연결이 해제되어 있거나 로컬 미저장 변경사항이 있으면 자동 확인하지 않으며 `태그 동기화 ↻`를 수동으로 누를 수 있습니다.

## 수정 파일

- `app.js`: GitHub Pages 저장소 루트에 교체. 업로드된 최신 `app(5).js`에 직전 getSize 패치를 포함한 버전을 기반으로 영상 자동 태그 부분만 수정했습니다.
- `VideoAnalysis.gs`: 기존 **Google Apps Script** 프로젝트의 같은 이름 스크립트 파일 내용 교체. 기존 `Code.gs`를 덮어쓰지 마세요.
- **교체하지 않는 파일**: `index.html`, `styles.css`, `Code.gs`. 이전 조회수/좋아요/댓글/인플루언서/캐러셀/Drive 수동 저장 기능 그대로 유지합니다.

## 적용 순서 (반드시 먼저 백업)

1. GitHub 저장소의 현재 `app.js`와 Apps Script의 `VideoAnalysis.gs`, Drive `refboard-data.json`을 백업합니다. 브라우저에 Drive에 저장하지 않은 레퍼런스가 있다면 **새로고침/Drive 불러오기부터 하지 마세요.**
2. **Apps Script의 기존 `VideoAnalysis.gs`**를 이번 버전으로 교체하고 저장합니다. `GEMINI_API_KEY`는 변경하지 않습니다.
3. **GitHub Pages의 `app.js`만 교체**하여 Commit → Push origin 합니다. HTML/CSS/기존 `Code.gs`를 덮어쓰지 않습니다.
4. 기존에 분석 완료한 영상에 태그가 적용되지 않았다면 Apps Script에서 **`mjrefBackfillVideoTags`를 1회 실행**합니다. 이 함수는 유효한 기존 태그만 붙이며 Gemini API 호출을 하지 않습니다.
5. 새로운 영상은 사이트에서 **태그 분석 준비 → Drive에 저장 → Apps Script의 `mjrefAnalyzePendingVideos` 실행** 순서로 진행합니다. 함수 1회 실행당 대기 영상 1개만 처리합니다. 실행 완료 시 Drive `refboard-data.json`의 `facets`에 태그가 이미 기록됩니다.
6. 사이트에서 해당 영상 카드를 열어두면 Drive 연결/미동기화 상태에 따라 태그가 자동 반영될 수 있습니다. 그렇지 않다면 영상 상세의 **`태그 동기화 ↻`**를 누르세요. `Drive 불러오기`는 전체 로컬 데이터가 교체될 수 있으므로 태그 확인 용도로 사용하지 않는 것이 안전합니다.
7. 실패 영상이 있다면 **`저장된 자료로 태그 재분류` → Drive에 저장 → `mjrefAnalyzePendingVideos`** 순서로 재시도합니다. 프레임이나 원본이 Drive에 없으면 `영상 태그 분석 준비`부터 진행해야 합니다. 정밀 분석 원본이 12MB를 넘으면 `빠른 분류`를 선택하세요.

## Drive 폴더 중복인 경우

Google Drive에 `refboard-assets` 폴더가 여러 개 존재하면 잘못된 JSON에 태그를 붙이는 일을 방지하기 위해 서버가 **오류로 중단**합니다. 실제 MJREF 사이트가 사용하는 폴더의 ID를 확인하고 Apps Script 스크립트 속성 `MJREF_DRIVE_FOLDER_ID`에 추가하면 그 폴더만 대상으로 삼습니다. 불확실한 상태에서 임의의 폴더 ID를 지정하거나 파일을 삭제하지 마세요.

## 분석 범위의 한계

- **빠른 분류**: 6개 정지 프레임에서 확인되는 비주얼/스토리/후킹만 분류. 실제 음성, 리듬, 협찬 계약, 시청자 반응을 추정하지 않습니다.
- **정밀 분류**: 영상·오디오를 함께 분석하되, 실제 원본이 Drive에 있고 Gemini 지원 형식이며 12MB 이하인 경우에만 가능합니다.
- `comments`, `likes`, `views`는 기존처럼 **직접 입력한 수치만 유지**됩니다. AI가 실제 성과를 예측하여 입력하지 않습니다.
- 일부 영상의 분석 오류가 계속된다면 Apps Script 실행 로그의 구체적인 오류(429, 미지원 코덱, 12MB 초과, 파일 ID 누락 등)를 확인하세요. 코덱에 따라 MP4(H.264) 또는 WebM 재인코딩이 필요할 수 있습니다.

## 검증 범위

- Node JS 문법 검사(`app.js`, `VideoAnalysis.gs`) 성공.

- **실제 사용자 Google Drive / Gemini API에 대한 네트워크·권한 통합 테스트는 하지 못했습니다.** 적용 후 짧은 테스트 영상 1개로 먼저 확인하세요.
