# MJREF — 빠른 추가 다중 이미지 자동 캐러셀 (2026-10-23)

## 무엇이 바뀌었나요?
- 빠른 추가의 **드래그 앤 드롭**과 **파일 선택**에서 이미지 2장 이상을 한 번에 넣으면, 레퍼런스 **1개(캐러셀)**로 등록합니다.
- 이미지 1장은 기존처럼 일반 이미지 레퍼런스 1개로 등록합니다.
- 영상은 개별 영상 카드로 등록합니다. 이미지를 2장 이상 + 영상을 함께 드롭하면, 이미지 1개 캐러셀 + 영상 별도 카드로 등록합니다.
- 캐러셀 슬라이드는 **파일명 자연 정렬**(`1,2,10`)을 따릅니다. 캐러셀 제목은 첫 파일명을 바탕으로 자동 생성하며 편집 가능합니다.
- 빠른 추가 영역에 위 동작을 안내하는 문구를 추가했습니다.

## 보존한 기능
- 2026-10-23 인플루언서 콘텐츠 분석 확장본의 상위 콘텐츠 분야 및 하위 분석 필터를 유지했습니다.
- 기존 드라이브 수동 저장(`💾 Drive에 저장`) 및 브라우저 로컬 저장 기능을 유지했습니다. 추가 직후 Drive 업로드는 실행되지 않습니다. **Drive에 영구 보관하려면 상단 저장 버튼을 직접 누르세요.**
- 캐러셀 슬라이드의 개별 File 객체 및 `localBlobKey`를 유지하여 기존 업로드/복원 경로에 그대로 전달합니다.
- 기존 항목, 태그, 브라우저 저장 키 및 Drive JSON 구조를 변경하지 않습니다.
- `+ 추가` 모달의 수동 캐러셀 만들기, 개별 이미지/영상 업로드 방식은 유지합니다.

## 설치
기존 코드 뒤에 복사·병합하지 마세요. 저장소를 백업한 다음 같은 경로의 `index.html`, `app.js`, `styles.css` **파일을 각각 교체**한 후 GitHub Desktop에서 커밋/Push origin으로 배포합니다. `Code.gs`는 수정하지 않습니다.

## 테스트
- JavaScript 정적 문법 검사 통과.
- Chromium UI 모의 테스트: 3장 드롭 시 캐러셀 1개, 파일 선택 2장 시 캐러셀 1개, 단일 이미지 시 이미지 카드 1개, 2장 이미지+영상 혼합 시 캐러셀과 영상 별도 카드, 데이터 직렬화/로컬 복원 구조 확인.
- 실제 Google Drive API 업로드와 브라우저 IndexedDB 파일 보관은 계정/브라우저 연결이 없어 직접 검증하지 못했습니다.

## 주의
현재 브라우저에 저장되지 않은 레퍼런스가 있을 수 있으므로 배포 전 JSON 백업 권장. 새로운 코드를 배포한 뒤에는 추가한 카드 수와 캐러셀 슬라이드 수를 확인하고, 상단 `Drive에 저장` 버튼을 누르세요.
