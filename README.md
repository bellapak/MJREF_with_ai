# MJREF — 콘텐츠 분석 분야 / 인플루언서 분석 확장 (2026-10-23)

## 이번 구조

레퍼런스를 광고/브랜드에 한정하지 않고 다음 4단계로 분석합니다.

1. **LEVEL 01 — 콘텐츠 분석 분야**: 광고·캠페인, 브랜드·BX, 인플루언서, SNS·커뮤니티, 정보·에디토리얼, 커머스·제품, 공간·경험, 문화·공연. 복수 선택 가능.
2. **LEVEL 02 — 공통 분석**: 활용 목적, 콘텐츠 역할, 콘텐츠 형식, 표현 톤, 적용 채널·매체, 업종 (6개).
3. **DEEP DIVE — 분야별 심화 분석**: 상위 분야를 선택하면 해당 분야 전용 태그만 노출. 예: 인플루언서 → 크리에이터 유형, 브랜드 협업 관계, 크리에이터 콘텐츠 형식, 신뢰·진정성 단서, 관찰된 오디언스 반응, 오디언스 관계 (6개).
4. **VISUAL — 비주얼 분석**: 색상군, 비주얼 스타일 (2개).

## 사용 예시

- 광고 협찬 콘텐츠: `인플루언서` + `광고·캠페인`을 둘 다 선택할 수 있습니다.
- 콘텐츠를 추가하거나 수정할 때 맨 위 **콘텐츠 분석 분야**를 고르면 상세 분석 태그가 동적으로 표시됩니다.
- 왼쪽 **최상위 분야 버튼**을 클릭하면 해당 분야의 레퍼런스로 검색되고, 전용 하위 필터가 열립니다. 분야 내 여러 선택지는 OR, 서로 다른 필터 축은 AND입니다.
- `전체 분야`를 선택하면 모든 레퍼런스를 볼 수 있으며 공통 + 비주얼 필터만 기본 표시합니다. 다른 분야의 활성화된 세부 필터가 있으면 해제하기 쉽도록 해당 필터를 계속 표시합니다.

## 기존 데이터/코드 호환성

- `refboard_v31_state` / `refboard-data.json` 구조와 Google 로그인 설정을 변경하지 않았습니다.
- `facets`의 기존/미인식 키 및 태그를 삭제하지 않습니다. 화면에 없는 기존 태그도 수정 시 보존됩니다.
- 과거 `purpose` 태그에서 의미가 분명한 값만 새 `contentArea`에 대응시킵니다. 인스타그램 링크라는 이유만으로 인플루언서 콘텐츠라고 단정하지 않습니다.
- 기존 레퍼런스가 새로운 전문 태그로 일괄 자동 분류되지는 않습니다. 상세 화면에서 태그를 부여할 수 있습니다.
- `Google Drive`는 기존 요구대로 **💾 Drive에 저장** 버튼을 클릭할 때만 저장합니다. 브라우저 로컬 저장은 자동입니다.
- **Apps Script `Code.gs`는 바꾸지 않았습니다.** AI 자동 분류가 새 인플루언서 필드를 직접 생성하려면 `Code.gs`의 프롬프트/스키마를 추후 변경해야 합니다.
- 오디언스 반응, 협업 관계, 신뢰 단서는 확인되는 정보만 선택하도록 설계했습니다. 조회수·매출·반응률 등을 근거 없이 추정하지 않습니다.

## 적용 전 유의 및 배포

1. 현재 GitHub `main` 브랜치를 백업하거나 정상 커밋을 기록합니다. 브라우저에만 저장된 레퍼런스가 있다면 데이터를 먼저 별도로 백업합니다.
2. 압축 안의 `index.html`, `styles.css`, `app.js` 세 파일을 저장소의 같은 경로에 **파일 교체**하세요. 이전 파일 내용을 뒤에 덧붙이거나 Git의 충돌 코드와 합치면 안 됩니다.
3. GitHub Desktop의 Changes에서 이 세 파일만 변경된 상태인지, `<<<<<<<`, `=======`, `>>>>>>>` 등이 없는지 확인합니다. 커밋 후 Push origin, GitHub Pages 배포를 확인합니다.
4. 사이트에서 `전체 분야 → 인플루언서` 선택, 레퍼런스 편집, 콘텐츠 분야 추가 및 수동 Drive 저장을 차례로 확인합니다.
5. 외부에서 Apps Script가 Drive 데이터를 갱신한 직후에는 `Drive 불러오기`가 로컬 미저장 변경사항을 덮어쓸 수 있습니다. 충돌 상황에서는 백업을 먼저 확보하세요.
