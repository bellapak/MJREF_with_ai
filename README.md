## 기존 레퍼런스 보호
- 기존 13축 분류, 선택지에 없는 태그, Apps Script의 미인식 신규 값도 JSON 필드에서 제거하지 않고 유지합니다.
- 기존 `benefit` → 새 `offer`, `appeal` → 새 `strategy`의 뜻이 명확한 일부 항목만 **보조 분류**로 연결합니다. 원래 태그는 삭제하지 않습니다.
- 레퍼런스 편집 시 화면에서 보이지 않는 기존 태그는 유지합니다.
- 기존 사진, 영상, 카피, 카테고리, 메모, 레퍼런스 원본 주소의 저장 구조는 변경하지 않았습니다.

## Google Drive
- 레퍼런스 변경은 브라우저에 자동 저장, **Google Drive는 상단 `💾 Drive에 저장` 클릭 시에만 저장**됩니다.
- 기존 Apps Script AI 분류 결과는 사이트의 `AI 분류 결과 반영` 클릭 시 불러옵니다.
- Apps Script 분류 모델은 별개이므로 **현재 `Code.gs`가 기존 분류 키로 저장한다면** 새 필드로 분석하게 하려면 `Code.gs`도 별도 업데이트가 필요합니다. 이번 배포 파일은 `Code.gs`를 건드리지 않습니다.
- `Drive 불러오기`는 로컬의 저장되지 않은 수정분을 덮어쓸 수 있으니 주의하세요. 특히 AI 분류 실행과 Drive 수동 저장을 동시에 실행하지 마세요.

## 배포 방법
1. 저장소 파일을 백업하거나 현재 커밋을 기록합니다. 로컬에서만 수정한 자료가 있다면 먼저 별도 백업합니다.
2. `index.html`, `app.js`, `styles.css` **이 세 파일만** GitHub 저장소의 같은 파일명과 교체합니다. `README.md` 교체는 선택 사항입니다.
3. GitHub Desktop의 Changes에서 `<<<<<<<`, `=======`, `>>>>>>>` 표시가 다시 생기지 않았는지 확인합니다.
4. 커밋 후 Push origin, GitHub Pages 배포를 확인합니다.
5. 사이트에서 전략 필터 8개, 비주얼 필터 2개가 표시되는지 확인한 뒤 카드 편집과 수동 저장을 테스트합니다.

## 기본 검사
- Node.js 문법 검사, 실제 headless Chromium에서 필터 렌더링/검색/태그 유지/로컬 저장 테스트 수행.
- 실제 Google OAuth 권한과 Drive 쓰기 API 동작은 로컬 테스트에서 확인할 수 없습니다.
