# MJREF · 콘텐츠 분석 분야 카운트 정합성 개선 (2026-11-18)

## 확인한 원인
기존 `app.js`의 '전체 분야'는 **일반 레퍼런스만** 집계하며, 상세페이지는 별도 탭으로 분리합니다. 기존 8개 분야별 숫자는 `facets.contentArea` 배열에 분야명이 있는 경우만 세었습니다. 따라서 **분야 미지정 콘텐츠는 어떤 분야에도 보이지 않고**, 한 콘텐츠에 태그가 두 개 이상 붙으면 **분야별 건수를 더한 값은 전체보다 커집니다**. 새/옛 코드가 저장한 다른 분야명도 기본 8개 버튼에는 없었습니다.

## 이번 수정
- 화면에 저장된 미디어 콘텐츠의 총수, 일반 레퍼런스 수, 상세페이지 수를 명확히 나눠 표시합니다. **카피 모음은 별도 데이터**라 이 숫자에서 제외합니다.
- `분야 지정`, `분야 미지정`, `복수 지정` 수를 보입니다. 기존 상세 분석 태그는 있지만 `contentArea`가 없다면 **분야 미지정**으로 집계합니다.
- **분야 미지정** 버튼을 새로 추가했습니다. 선택하면 실제 분야 태그가 없는 콘텐츠만 모아서 확인·수동 분류할 수 있습니다.
- 기본 8개 분야에 없는 기존 저장 태그도 **기존 태그** 버튼으로 표시하고 검색할 수 있습니다. 임의로 태그 이름을 바꾸거나 분류를 추정하지 않습니다.
- 검색, 파일 유형, 다른 분석 태그, 분류 상태 필터 변경 시 **분야별 버튼의 건수도 해당 조건에 맞춰 다시 계산**합니다. 이때 분야 선택 자체는 빼고 분야별 숫자를 계산하므로, 하나만 선택했을 때 숫자와 검색 결과 건수가 일치합니다.
- **복수 분야 선택(OR)**은 그대로 유지합니다. 한 콘텐츠에 광고+SNS 태그가 있으면 두 분야 모두 1건씩 표기하지만 전체 레퍼런스에는 1건입니다.
- 카드는 `items` 배열의 **콘텐츠 한 건당 1건**으로 셉니다. 캐러셀의 슬라이드 개수와 별개입니다.
- 기존 `Code.gs`, 상세페이지 분류용 Apps Script, Gemini/OpenAI API, Drive 데이터 구조, 기존 레퍼런스의 태그·파일·메모는 변경하지 않았습니다.

## 배포 방법
1. 사이트에서 `Drive에 저장`으로 운영 자료를 백업하고, 기존 GitHub 코드를 백업합니다.
2. 이 묶음의 **`app.js`, `index.html`, `styles.css`**를 배포 사이트의 같은 이름 파일과 교체합니다.
3. GitHub Pages에서 새로고침하여 **'콘텐츠 분석 분야'** 아래 집계 요약과 **분야 미지정** 버튼을 확인합니다.
4. `분야 미지정`을 누르면 해당 자료만 나오고, 상세 편집창에서 실제 해당하는 분야를 직접 선택하여 `수정 저장`할 수 있습니다. 다른 기기와 공유하려면 `Drive에 저장`을 별도 실행합니다.

## 검증·한계
- `node --check app.js` 통과
- 순수 JS 집계·필터 **16개 테스트** 통과
- Chromium의 외부 URL 접근 제한을 피한 **내장 페이지 브라우저 시뮬레이션**에서 총수, 분야 미지정, OR 필터, 검색 건수 6개 항목 통과(실제 사이트 동작 전반을 검증한 것은 아님)
- **운영 Google Drive JSON을 제공받지는 않았으므로 사용자 데이터의 실제 건수는 확인하지 못했습니다.** 배포 후에도 전체 카운트가 예상보다 적다면, 먼저 브라우저에 로드된 데이터와 Drive의 저장 데이터가 같은 버전인지 확인해야 합니다. 코드가 사용 중인 `referenceItems()`의 결과는 상세페이지를 제외합니다.
