# MJREF Drive 인증 및 저장 복구 · 2026-11-18

## Google 인증창 오류 수정

기존 저장 버튼은 이미지 캐시를 처리한 뒤 인증창을 열었고, 인증이 실패하면 창을 다시 열었습니다. 이번 판에서는 인증이 필요한 경우 **‘Drive에 저장’을 누른 즉시** 인증창을 한 번 열고, 승인이 완료되면 Drive로 전송합니다. 상단 **‘Google 연결’**로 미리 인증해도 됩니다.

- **인증창을 닫았거나 팝업이 차단됨** — Drive 전송을 시작하기 전에 중단합니다. 하단 안내를 확인한 뒤 ‘Google 연결’에서 기존 Drive 계정을 선택하고, 다시 ‘Drive에 저장’을 누릅니다.
- **저장 중 연결 만료** — 인증창을 자동으로 열지 않습니다. ‘Google 연결’ 후 다시 저장하면 앞서 업로드하고 파일 ID까지 기록한 미디어는 재사용합니다.
- **Drive 요청 오류** — 하단에 실패 단계와 Drive가 반환한 HTTP 상태를 표시합니다. 목록 전송은 완료됐지만 저장 확인에 실패한 경우도 구분합니다.
- **저장 성공** — Drive에서 목록을 다시 읽어 전송한 내용과 일치할 때 ‘Google Drive 저장 및 재확인 완료’를 표시합니다.

직전 저장 복구판을 이미 적용한 경우 GitHub Pages의 **`app.js`와 `index.html`**을 교체합니다. 기존 CSS와 Apps Script 설정을 사용할 수 있습니다. 이전 버전에서 업데이트하는 경우 아래 전체 적용 순서를 따릅니다.

이번 변경은 JavaScript 문법 검사와 인증 창 닫힘·차단, 권한 거부, 연결 만료 후 재저장, 업로드 실패, 저장 확인 실패, 동시 클릭 등을 포함한 모의 테스트 10건으로 확인했습니다. 운영 사이트 배포와 실제 Google 계정 저장은 확인이 필요합니다.

## 이전 저장 복구판에서 포함된 변경

## 결론

기존 저장 데이터가 실제로 어떤 단계에서 실패했는지는 운영 브라우저/Google Drive 로그가 없어 확정하지 못했습니다. 다만 첨부된 `app.js`에서 **저장 실패를 감추거나 콘텐츠를 자동으로 제거할 수 있는 코드**를 확인해 수정했습니다.

### 코드에서 확인한 문제

1. 상세 편집의 `수정 저장`은 `saveData()`의 완료를 기다리지 않고 **무조건 ‘수정 저장 완료’**를 표시했습니다. `localStorage` 용량 부족이면 실제로는 저장되지 않아도 완료로 보일 수 있었습니다.
2. 새 콘텐츠 추가 화면은 저장 완료를 확인하기 전에 창을 닫았습니다. 저장 실패 시 입력 내용이 없어졌다고 느낄 수 있었습니다.
3. `saveLocalBlob`에서 IndexedDB 오류를 내부적으로 삼켜, 새로고침 후 이미지 원본이 사라질 수 있었습니다.
4. Google Drive에 저장하기 전에 상세페이지 AI 전용 JSON을 필수로 조회해, **AI 결과 파일 오류가 일반 레퍼런스의 Drive 저장까지 막는 경로**가 있었습니다.
5. 브라우저가 이전에 저장한 데이터 중 미디어 연결이 없는 항목을 시작 시 자동 제거하고, 같은 파일명/체크섬의 콘텐츠를 삭제하는 코드가 있었습니다. 미디어 연결 불량과 콘텐츠 삭제는 별개이므로 자동 제거를 중지했습니다.
6. Drive 저장 후 확인 없이 완료 토스트를 표시하고, 실패 알림은 약 2초 후 사라졌습니다.

## 변경 내용

- `수정 저장`이 브라우저 저장 결과를 **기다린 다음** 성공 메시지를 표시합니다.
- 새 콘텐츠 추가가 실패하면 **입력 폼을 유지**하고 중복 추가되지 않도록 롤백합니다.
- 새 파일의 IndexedDB 원본 저장 실패와 `localStorage` 용량 부족을 **하단 지속 안내**로 보여줍니다.
- 저장 실패 안내에는 **JSON 긴급 백업** 버튼을 제공합니다. JSON에는 콘텐츠 메타데이터·카피·태그가 포함되지만, Drive에 업로드되지 않은 이미지/영상 파일의 바이너리는 포함되지 않습니다. 원본 미디어는 별도 보관해야 합니다.
- `refboard-pdp-ai.json` 접근에 실패해도 일반 `refboard-data.json` 저장을 계속 시도합니다. 실패 사실은 따로 알립니다.
- 기존 `refboard-data.json` ID를 다시 확인해 덮어쓰며, **업로드 후 Drive 파일을 다시 조회해 일치 여부까지 검사**합니다. 일치하지 않으면 성공이라고 표시하지 않습니다.
- 자동 원본 누락 정리, 파일명 일치에 의한 콘텐츠 삭제, MD5 기반 자동 콘텐츠 삭제를 중지했습니다. **직접 삭제 버튼은 기존대로 유지**합니다.
- 브라우저 저장과 Drive 저장이 **별개**임을 메시지로 구분합니다.

## 적용 방법

1. 운영 사이트에서 이미 저장한 내용은 가급적 먼저 **Drive에 저장**하세요. 다만 지금 Drive 저장이 실패한다면 **‘Drive 불러오기’를 먼저 누르지 마세요.** 이전 데이터로 덮일 수 있습니다.
2. 현재 GitHub 파일(`app.js`, `index.html`, `styles.css`)을 별도 폴더에 백업합니다.
3. 이 ZIP의 **세 파일을 함께** 교체하고 GitHub Pages에 배포합니다.
4. 브라우저에서 강력 새로고침(Windows `Ctrl+Shift+R`, Mac `⌘+Shift+R`)합니다.
5. 테스트 레퍼런스의 제목/분야/메모 한 곳을 편집 → **수정 저장** → 안내에서 ‘브라우저 저장 완료’ 확인 → 새로고침하여 값이 유지되는지 확인합니다.
6. 상단 **Drive에 저장** → 안내에서 ‘Drive 저장 및 재확인 완료’를 확인합니다. 정상 확인 후 다른 기기에서 **Drive 불러오기**를 시험합니다.
7. 실패하면 하단 안내에 **어떤 단계에서 실패했는지** 남습니다. 해당 문구만 알려주면 구체적으로 진단할 수 있습니다. API 키 등 비밀은 공유하지 마세요.

## 주의

- 이 패치는 **사이트 저장 기능만** 수정합니다. 기존 일반 분류 `Code.gs`, 상세페이지 `DetailPageClassifier.gs`, AI API 키/트리거는 그대로 유지합니다.
- 저장된 콘텐츠의 AI 분석 분야를 자동으로 채우거나 기존 태그를 바꾸지 않습니다.
- 같은 파일을 참조하는 카드들도 별도 ID의 기록이면 자동으로 삭제하지 않습니다. 따라서 기존 자동 정리로 사라졌던 기록이 원본 데이터에 남아 있는 경우 중복 카드가 보일 수 있으나, 데이터를 잃지 않는 쪽을 우선합니다.
- 아직 운영 중인 브라우저의 실제 저장 실패 원인 및 실제 Google Drive 계정 업로드/다운로드는 확인하지 못했습니다. 검증은 브라우저 내 모의 Drive API로 수행했습니다.
