## 변경 사항
- Google Drive 파일 업로드를 재개 가능한(Resumable) 업로드로 전환해 5MB를 넘는 사진도 4MB 단위로 나누어 전송합니다.
- 캐러셀 슬라이드를 개별적으로 순차 업로드합니다. 한 장이 실패해도 이미 성공한 슬라이드의 Drive 파일 ID를 로컬에 기록해 다음 재시도에서 중복 업로드하지 않습니다.
- 새로고침 후 `_file` 데이터가 사라져도 IndexedDB `localBlobKey`에 남아 있는 원본 사진을 불러와 저장합니다.
- 네트워크 일시 실패 시 업로드 세션의 진행 상태를 확인한 뒤 최대 3회 재시도합니다. 반복 실패 시 어느 슬라이드에서 멈췄는지 알 수 있도록 메시지를 바꿨습니다.
- 모든 사진과 메타데이터 저장이 성공한 후에만 삭제 예약을 실제 Drive에 반영합니다.
- 수동 Drive 저장 및 기존 상위/인플루언서 필터 구조는 그대로입니다.

## 확인 방법
1. **기존 데이터 백업을 먼저 확보하세요.** Drive에 저장되지 않은 새 이미지·캐러셀이 있으면 업로드 전 브라우저 데이터를 지우지 마세요.
2. 파일 교체 후 사이트 새로고침 → 기존 레퍼런스와 캐러셀이 남아 있는지 확인합니다.
3. 2~3장 캐러셀을 추가한 뒤 **상단 `Drive에 저장` 버튼**을 직접 누릅니다.
4. `Google Drive 저장 완료` 표시를 확인하고 새로고침 후 캐러셀 슬라이드가 모두 보이는지 확인합니다.
5. 다시 실패하면 Chrome 개발자 도구 **Network**의 실패한 요청 URL (개인 토큰은 제외), 상태 코드, 응답 오류를 확인하세요. 브라우저 보안정책, 인증 및 구글 API 장애 등은 코드 변경만으로 항상 해결할 수는 없습니다.

## 검증 범위
- Node `--check` JavaScript 문법 검사 통과.
- Chromium 모의 업로드 테스트: 이미지 세 장→캐러셀 한 개, 6MB 파일 두 청크, 중간 네트워크 오류/308 진행 상태 조회/재시도, 로컬 캐시로부터 파일 복원, Drive ID 저장 테스트 통과.
- **실제 Google Drive API에 대한 사용자의 계정 기반 업로드 및 브라우저 IndexedDB 실환경 테스트는 수행하지 않았습니다.**
